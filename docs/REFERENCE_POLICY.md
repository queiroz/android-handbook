# Reference policy

The handbook should be trustworthy enough for senior interview preparation. References are evidence, not decoration.

## Preferred sources

Use primary sources whenever available:

1. Official Android Developers documentation
2. AOSP documentation and source code
3. Official Kotlin and kotlinx.coroutines documentation
4. Official Jetpack library documentation
5. Android Developers Blog
6. Official Google I/O and Android Dev Summit sessions
7. Relevant standards such as HTTP or TLS specifications

Secondary sources may add explanation but should not be the sole support for important technical claims when primary material exists.

## Rules

- Open and verify every cited source.
- Cite the precise page supporting the claim.
- Avoid references that merely repeat another unsourced article.
- Record Android, Kotlin, Compose, or library version context where behaviour changes.
- Do not imply a private implementation detail is a stable public guarantee.
- Do not invent company interview frequency claims.
- Do not publish a question with placeholder references.

## Research notes

Temporary research notes may live outside the final MDX during drafting. The published page should contain only useful references for readers, not a dump of every search result.
